## Context

C 方案的 CPU 生成与缓存已接入，完整说明见 `doc/battlefield_fog_cache_development.md`：47 规则、14 基础轮廓、完整浓度键与 D4 复用，2,048 项字典覆盖全部 1,652 合法稳态及少量辅助占位，生成后常驻至战场退出，不做稳态 LRU。CPU 过渡保留 alpha，无设备回读；已验证 7,170 条断言，人工视觉和移动端性能待验收。下文前阶段单图渐变由此路线替代。

- `BulletRange.get_reachable_cells()` 已实现方形范围枚举、DDA、方向墙、障碍和楼层高度判定；传入 `unit_cells` 后还会阻挡同层弹道，默认不包含原点。
- 攻击模式在 `_enter_attack()` 中从全部存活敌人收集占格，然后计算 `attack_cells`。不能先按可见性过滤敌人，否则无法发现视距以外、射程以内的目标，也会改变单位阻挡弹道的结果。
- `_run_enemy_phase()` 的流血聚焦和 `_play_enemy_turn()` 的行动聚焦是两个入口，必须统一门控。
- `_plan_has_visible_action()` 当前只表示“计划中有实际动作”，不是玩家视野判定。不能据此跳过迷雾中敌人的回合。
- 世界单位和 HUD 均使用多层绘制，二层有视觉偏移；`UnitStatusWidget` 在 CanvasLayer 中，不会被世界中的遮罩挡住。
- 当前脚步在第一格起播后按单位缓存，后续格子直接返回；结束移动后才执行 450ms 保底和 80ms 淡出。只在起播处添加距离判断不足以覆盖听力进出边界。

## Goals / Non-Goals

**Goals**

- 视野、攻击临时揭示和听力互相独立，具有统一、可测试的查询入口。
- 不改变既有攻击命中、武器射程、寻路占格和敌人决策。
- 所有地图查询和遮罩都携带 `(grid, level)`，正确处理换层、偏移及重叠绘制。
- 美术先交付用户评审，技术验收与视觉取舍分开。

**Non-Goals**

- 历史探索记忆、最后已知敌人位置、视野共享、光照或朝向视锥。
- 听声定位、隔音、垂直声学、脚步素材更换或枪声听力限制。
- 敌人 AI 感知系统改造，以及现有攻击遮罩内容重做。

## Decisions

### 1. 关卡配置控制视距，角色定义提供听力

2026-11-23 起视距唯一来源为关卡 `fog_of_war.vision_range`，默认 16；移除角色视距字段及读取接口。`fog_of_war.enabled` 默认 true，false 时全图显示且遮罩 alpha 为 0；听力不受其影响。`show_blocking_containers` 默认 false，新手关显式设为 true。听力仍由角色 `hearing_range` 定义，默认 12，经 `get_hearing_range()` 读取。视距和听力允许 0、负值钳制到 0。不改存档和武器配置。

### 2. 用同一射线算法、不同输入表达视野与攻击

新增 `BattleVisibility` 管理以下集合，并提供按 `(grid, level)` 的查询：

```text
sight_cells = BulletRange.get_reachable_cells(
    player.grid_pos, player.current_level, vision_range + 3, [], true, false
) + player_current_cell
base_visible = sight_cells 内距离 <= vision_range 的格子

attack_reveal = attack_cells  (仅 ATTACK_STATE；其余状态为空)
effective_visible = base_visible ∪ attack_reveal
enemy_visible = effective_visible ∪ (sight_cells 内逻辑浓度 <= 0.7 的格子)
```

`effective_visible` 表示完全揭示，不能直接用于敌人显隐。距离采用切比雪夫距离。完全揭示格浓度为 0；视距外第 1/2/3 格为 0.5/0.6/0.7，再远为 0.8；视距内射线被挡住为 0.8。墙后即使距离浓度 <=0.7 也不显示敌人。射线只扩到 R+3，不每次扫描全图。

空单位列表使角色不阻挡基础视线；`allow_target_obstacle = true` 允许看到射线终点的柜子、掩体等障碍，但不穿过中间障碍。新增 `respect_height_limits: bool = true`，贯穿 `get_reachable_cells()`、`can_reach_cell()` 与内部路径检查；视觉传入 `false`，同时关闭低打高仅邻格可达的分支和路径中高层地面截断。视觉仍逐格执行 DDA、方向墙、静态障碍和动态容器遮挡检查，不因关闭高度限制而穿墙。攻击、敌人 AI、容器搜索沿用默认值，行为不变。

攻击范围保持原算法及其真实单位占格参数；不把不可见敌人从 `_collect_targetable_cells()` 删除。视野集合只影响显示和玩家输入，不能作为世界实际单位列表。

基础可见性与 `UnitIntelTracker` 中的“已揭示属性”相互独立。即使属性已知，不满足敌人可见阈值仍隐藏；重新出现时可以沿用既有属性情报。

### 3. 无探索记忆，逐格刷新而非每帧重算全地图

- 开局在角色、楼层、动态障碍和敌人准备完毕后计算，避免首帧全图暴露。
- 玩家 `grid_position_changed` 时重算基础视野；换层使用新楼层。信号当前先于世界坐标落位发出，回调以逻辑格为准；需要世界位置的表现延迟到落位后更新。
- 敌人移动时更新该单位显示；若攻击范围依赖的占格发生变化，则重算当前攻击范围及临时揭示。
- 玩家配置/装备变化、阻挡容器生成或销毁时按影响刷新；不在 `_process()` 中逐帧执行 DDA。
- 状态退出先清空临时揭示并同步面板，状态进入攻击模式则在计算完整攻击范围后应用揭示。
- 攻击提交后如状态已退出 ATTACK_STATE，地图立即恢复基础视野；既有攻击遮罩按已提交目标完成，不借此保留额外地图可见格。

### 4. 独立分层迷雾与显式对象隐藏同时使用

`BattleFog` 按已注册楼层生成独立 Node2D 容器，每个覆盖格放置一个 Sprite2D，中心对齐 `ground.map_to_local(grid)`。读取有效可见格后分别调整各格 alpha，使用该层坐标变换与视觉偏移，不能将所有楼层压到同一世界网格。

逐格 `modulate:a` 用 0.25 秒 Sine EaseInOut 向 0/0.5/0.6/0.7/0.8 过渡；相同目标不重启 tween，反向先取消旧 tween 再从当前值继续。淡出至 0 后释放 Sprite2D，其余结束保留；开局直接设置目标浓度。Tween 绑定 Sprite 生命周期，场景退出自动取消。敌人显隐及点击权限按逻辑浓度和视线判定，不等渐变或读取图片像素判断。技术占位核心为 alpha=1，避免多乘一次透明度。

迷雾只覆盖可能成为单位站位的格子：地面 `terrain == 0`，且障碍层没有 tile 或其 `can_walk == true`。墙体、不可行走障碍和非可走地形始终不铺雾，避免在不可进入区域制造大块深色遮罩。

绘制顺序按楼层保留“地面 → 障碍/单位 → HUD → 本层迷雾 → 上层地面”。当前 z_index 排布紧凑，实现时为楼层分配足够的绘制区间，保持单位现有“障碍层 + 1”的约定；全局路径线虽位于高层，也必须过滤隐藏部分，不能穿透迷雾泄露地图。禁止用一张覆盖所有楼层的顶层格子图简单相叠，避免低层雾盖住已可见的高层。

敌人不满足 `is_enemy_visible()` 时显式隐藏。点击、伤口反馈、面板、镜头和敌方路径提示共用该接口。容器使用 `is_container_visible()`，基础揭示或 `show_blocking_containers=true && can_walk=false` 时显示。渲染器只免除这些阻挡容器格的雾片，不将格子写入可见集合，不影响敌人判定。`can_walk=true` 的箱子/丢弃物继续按完全揭示显示。撤离标记仍按完全揭示格显示。容器菜单和搜索提交也检查容器可见性，搜索射程/AP 不变。

不修改移动 BFS 与路径结果；移动高亮/路径只绘制当前可见部分，不因迷雾将实际可达格从寻路数据中删除。

### 5. 敌方行动开始时冻结镜头权限

在每个敌人回合状态结算前，取其当前逻辑位置并查询 `is_enemy_visible()`（包含无阻挡的 <=70% 格），冻结 `may_focus`，同时用于流血和后续行动聚焦。关闭迷雾时所有敌人通过门控。

- `may_focus = false`：不聚焦，也不在中途进视野后补聚焦；仍完整执行计划。
- `may_focus = true`：保留“有状态反馈或有实际动作才聚焦”的既有行为。
- 行动路径预告只绘制满足敌人可见判定的格子，不揭示未来路径上的隐藏节点。每步移动实时判定显隐；面板只在当前敌人可见时展示。
- 本轮没有任何敌人触发聚焦时，不为隐藏敌人额外播放镜头归位动画；手动拖拽仍保持可用。
- 隐藏敌人的流血数值和死亡照常结算，但不显示其世界飘字；掉落容器生成后按当前视野决定显隐。

### 6. 每格进行听力门控，管理完整播放器生命周期

`_on_unit_step_taken()` 的处理分为独立的可见性刷新和声音处理；不能由于 `_sfx == null` 或已有播放器就提前跳过视野刷新。

敌人每一步以新格计算二维曼哈顿距离，不加楼层或障碍惩罚：

- 范围外且无播放器：不启动。
- 范围内且无有效在播播放器：启动现有单位 `move_step` cue。
- 范围内且在播放：继续，不叠加播放；已有播放器自然结束后，下一个可听步允许重新起播。
- 范围外且在播放：立即停止，取消该播放器的待执行保底/淡出 tween，清除缓存。

移动完成时，可听脚步仍沿用原来的保底与淡出；超出范围停声、单位死亡和退出战场不等待保底。快速重新进入范围时，旧停止回调不能影响新播放器，也不能留下尾音。玩家自身脚步不走敌人听力门控。

## Asset Plan

资产类别采用 `game-art` 的 `tile_overlay`，单张 64×64 RGBA PNG，一个 grid 一个中央独立图案，四周至少各 4px alpha = 0，主体可以不透明。二次元为主、少量浮世绘影响，不做全图朦胧。生成 1024 级母版，抠底后保留原色，禁止小图放大冒充母版。此方向取代无缝整面平铺。

候选、母版、平铺预览均先放 `_review/`。Agent 只检测尺寸、格式、alpha、可加载性和接线，不判断风格优劣、可读性或择优。用户确认后才复制到正式目录、登记 manifest 并连接场景。

## Risks / Validation

- 视觉不继承枪线高度限制；只取消高度造成的范围限制，不增加更写实的视觉高度模型，墙体和实际障碍仍可遮挡。
- 透明留边有意允许地图透出，不能依赖遮罩节点有无来决定敌人是否显示。正式素材未批准时使用中央不透明核心方块技术占位，由节点控制分档浓度，不自动加载 `_review/`。
- 跨层偏移与单位上半身越格需要真实场景回归，不能仅验证可见集合。
- CanvasLayer 面板不受世界迷雾遮挡，需要显式关闭和输入过滤。
- 保留攻击遮罩会展示现有攻击者演出，但不揭示其战场格子；若要连攻击者身份也隐藏，需要另行设计遮罩规则。
- 当前仓库未发现常设自动化测试目录。实现时用 Godot 临时无头测试场景做逻辑断言，验证后清理，不为本次新增独立测试框架。

## Migration / Rollout

先确认本提案，再制作并交付美术候选；逻辑可在评审期间推进，但正式贴图接线等待用户批准。完成功能、无头校验、文档同步后交用户实机评审；不由 Agent 宣告视觉评审通过。用户验收后合并能力规格并归档 change，不在本阶段提前归档。

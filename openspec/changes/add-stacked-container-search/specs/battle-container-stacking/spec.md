## ADDED Requirements

### Requirement: 同格容器查询返回全部候选

系统 SHALL 提供按 `grid + level` 查询同格全部 `BattleContainer` 的能力，任何“选一个容器”的入口 MUST 建立在完整候选集合之上，不得以遍历顺序上的第一个匹配作为结果。

#### Scenario: 同格存在多个战利品箱
- **WHEN** 同一 `grid + level` 上存在 2 个以上敌人掉落容器
- **THEN** 查询返回全部容器
- **AND** 右键入口与站立行动菜单入口 MUST 使用同一套优先级规则从候选中挑选默认目标

#### Scenario: 同格同时存在丢弃物堆与战利品箱
- **WHEN** 玩家所在格同时有一个丢弃物堆和一个敌人掉落容器
- **THEN** 两者都出现在候选集合中
- **AND** 丢弃物堆 MUST NOT 被并入战利品箱，二者保持独立节点与独立临时容器 ID

### Requirement: 默认目标与视觉最上层一致

同格候选的默认目标 SHALL 按两档优先级选择：没搜过（`is_opened == false`）> 搜过（`is_opened == true`）。丢弃物 MUST NOT 参与分档，恒定视为第 0 档。同档 MUST 取绘制在最上层的容器。

容器的绘制顺序 SHALL 与优先级保持同步：容器生成、首次打开、搜空、合并追加掉落时都 MUST 重排同格兄弟顺序，使优先级最高者绘制在最上层。重排 MUST NOT 通过抬高 `z_index` 实现（单位占用 `obstacle.z_index + 1`）。

#### Scenario: closed 容器与 opened 容器同格
- **WHEN** 同格存在没搜过的容器 A 与搜过的容器 B
- **THEN** A 绘制在 B 之上
- **AND** 右键与站立菜单的默认目标 MUST 是 A

#### Scenario: 丢弃物与没搜过的容器同格
- **WHEN** 同格存在一个丢弃物和一个没搜过的战利品箱
- **THEN** 两者同属第 0 档，默认目标取绘制在最上层的那个
- **AND** 丢弃物 MUST NOT 因为被搜过而降档

#### Scenario: 后生成但优先级更低的容器
- **WHEN** 容器 B 后生成但已搜过，容器 A 先生成且没搜过
- **THEN** 默认目标 MUST 是 A，即使 B 是树序最后者
- **AND** B MUST NOT 绘制在 A 之上

### Requirement: 0 AP 目标始终可打开

AP 成本为 0 的目标（已搜过的容器、丢弃物）MUST 始终可以打开搜索面板，即使已搜空；打开时 MUST NOT 扣除 AP。搜索项的可用性只由“是否在 1 格攻击射线内”和“AP 是否足够”决定。

#### Scenario: 打开已搜空的容器
- **WHEN** 玩家选择一个已搜空的容器
- **THEN** 搜索面板正常打开且内容为空
- **AND** AP 不减少
- **AND** 该行动项 MUST NOT 被禁用
- **AND** 动词显示为 `查看（已空）`

#### Scenario: 格子上的丢弃物
- **WHEN** 玩家所在格存在丢弃物
- **THEN** 右键角色的行动菜单 MUST 出现可用的搜索项
- **AND** 该次搜索成本为 `0 AP`

#### Scenario: 超出射程
- **WHEN** 目标容器不在 1 格攻击射线内
- **THEN** 该行动项禁用并给出原因，即使它成本为 0 AP

### Requirement: 同格多目标由列表菜单显式选择

同格候选数 ≥ 2 时，右键地图容器与右键站在容器格上的角色两个入口 SHALL 收敛到同一个容器列表菜单；候选数为 1 时 MUST 保持现有单按钮行为与文案不变。列表每一行 MUST 显示容器名称、状态动词与 AP 成本，并独立判定可用性与禁用原因。搜索会扣 AP，系统 MUST NOT 在未让玩家确认目标的情况下自动切换到下一个容器。

#### Scenario: 右键地图容器，同格 2 个候选
- **WHEN** 玩家右键一个同格存在 2 个容器的格子
- **THEN** 弹出列表菜单，标题体现目标数量
- **AND** 行序与优先级一致，第一行即默认目标
- **AND** 每行显示各自的 AP 成本与动词（没搜过 `搜索（N AP）`、搜过有货 `继续搜索（0 AP）`、搜过已空 `查看（已空）（0 AP）`）

#### Scenario: 右键站在容器格上的角色，同格 2 个候选
- **WHEN** 玩家右键自己且所在格存在 2 个容器
- **THEN** 行动菜单搜索项文案体现同格目标数量
- **AND** 点击后关闭行动菜单并弹出同一个列表菜单
- **AND** 行动菜单 MUST NOT 内嵌可变长度列表

#### Scenario: 候选行不可用
- **WHEN** 某个候选超出 1 格攻击射线，或需要 AP 而玩家 AP 不足
- **THEN** 对应行禁用并给出原因
- **AND** 点击禁用行 MUST NOT 扣 AP 或打开面板
- **AND** 已搜空的 0 AP 候选 MUST NOT 因为“已搜空”被禁用

#### Scenario: 同格仅 1 个候选
- **WHEN** 玩家右键只有 1 个容器的格子
- **THEN** 行为与文案与改动前完全一致（单按钮 `搜索` / `继续搜索`）

### Requirement: 全部同格战利品可达

同格所有容器 MUST 都能被玩家从菜单中选择并打开，不得因为默认目标固定而永久不可达。

#### Scenario: 依次搜空同格 3 个容器
- **WHEN** 玩家在有 3 个容器的格子上反复使用右键菜单
- **THEN** 每次都可以通过列表菜单选择任一容器
- **AND** 3 个容器的物品最终都能进入临时物资面板

### Requirement: 搜索必须与角色位于同一层

容器 MUST 只允许被位于同一 `level` 的角色搜索，该条件优先级高于 `requires_attack_range` 的短路规则，因此丢弃物同样受约束。跨层容器 MAY 出现在候选列表中，但 MUST 为禁用状态并给出“需要与角色位于同一层。”的原因。

#### Scenario: 站在上层搜下层容器
- **WHEN** 角色位于 level 2，目标容器位于 level 1 且处于 1 格攻击射线的邻层可达范围内
- **THEN** `can_be_searched_by()` MUST 返回 false
- **AND** 直接调用搜索 MUST NOT 打开容器、MUST NOT 扣 AP

#### Scenario: 跨层丢弃物
- **WHEN** 角色位于 level 2，目标为 level 1 的丢弃物（`requires_attack_range == false`）
- **THEN** 该丢弃物 MUST NOT 可被搜索

#### Scenario: 同层同格
- **WHEN** 角色与容器位于同一 `level` 且同一格
- **THEN** 可搜索判定通过，与改动前一致

### Requirement: AP 成本文案统一

所有展示 AP 成本的位置 SHALL 统一写作 `N AP`，MUST NOT 使用“免费”字样；0 AP 写作 `0 AP`。

#### Scenario: 已打开的容器
- **WHEN** 容器 `is_opened == true`
- **THEN** 容器菜单、行动菜单与搜索状态栏都显示 `0 AP`

#### Scenario: 丢弃物
- **WHEN** 目标为丢弃物
- **THEN** 成本显示为 `0 AP`

### Requirement: 菜单宽度容纳完整文案

容器菜单与行动菜单的宽度 SHALL 按最宽一行文案动态计算，并 MUST 在字体无法测量（缺字形或无字体环境）时用字符数兜底估算，保证容器名与动词不被截断。宽度 MUST 有上下限（容器菜单 260/320 ~ 560，行动菜单 186 ~ 420）。

#### Scenario: 长容器名
- **WHEN** 列表行文案为 `掠夺兵战利品箱 ×2 · 查看（已空）`
- **THEN** 菜单宽度 MUST 大于等于该行文字宽度 + 成本标签宽度 + 内边距

#### Scenario: 无字体环境
- **WHEN** `get_string_size()` 返回 0
- **THEN** 宽度 MUST 由字符数估算兜底，且不低于下限

### Requirement: 掉落播种不得静默丢失物品

首次搜索把配置掉落写入临时容器时，写入失败的物品 MUST 保留在待播种队列，MUST NOT 被标记为已播种；失败时 MUST 在状态栏提示剩余数量，物品 id 无效时 MUST 输出告警。

#### Scenario: 临时容器容量不足
- **WHEN** 配置掉落数量超过临时容器容量
- **THEN** 已写入的物品保留在临时容器中
- **AND** 未写入的物品留在待播种队列
- **AND** 状态栏提示剩余未取出数量
- **AND** 容器 MUST NOT 被标记为已搜空

#### Scenario: 物品 id 不存在
- **WHEN** 掉落配置引用了 ItemDB 中不存在的物品 id
- **THEN** 该物品留在待播种队列并输出告警，MUST NOT 静默消失

#### Scenario: 二次搜索继续播种
- **WHEN** 玩家取走部分物品后再次搜索同一容器
- **THEN** 待播种队列中剩余物品继续写入临时容器

# 战场迷雾 C 方案：CPU 按需生成与缓存开发文档

> 日期：2026-11-23
> 状态：核心实现已接入战场；逻辑、缓存、像素接缝与生命周期检查通过。移动端性能及人工视觉验收待完成。
> 上游规则：`battlefield_combat_design.md` §10。视觉方向：`battlefield_fog_visual_proposal.md`。
> 本文取代此前“必须预制完整图集”的技术路线；保留 C 的相邻融合方向，采用用户选定的 47 邻接规则，允许 90° 旋转和镜像复用。CPU 仅在缓存缺失时生产小贴图，不引入自定义 Shader、Compute 或屏幕实时模糊。

## 1. 实施结论

**第一版无需预制母图文件。**已用确定性的 CPU 配方生成 14 种基础轮廓，并对实际出现的“轮廓＋浓度邻接”生成最终 RGBA 小图，保存在有容量上限的内存缓存中。

**缓存容量已定为 2,048 项。**完整合法稳定态最多 1,652 种，单一样式下全部容得下。稳态资源按需生成后保留到战场退出，不实现常规 LRU 淘汰、双向链表或稳态 pin 计数。

| 资源层级 | 数量 | 何时产生 | 是否提前存 PNG |
|---|---:|---|---|
| 8 邻域归一化/变换查找表 | 256 条小记录 | 初始化枚举，可直接写入代码生成 | 否 |
| 二值基础轮廓 | **14 种** | 首次使用；也可进入战场时分批预热 | 否 |
| 同浓度最终贴图 | 当前规则 **26 种**；生成器通用能力最多 14×4＝56 | 首次遇到对应轮廓与浓度 | 否 |
| 混合浓度最终贴图 | R=16 为 **1,556 种**；兼容 R=0 为 1,626 | 缓存未命中时 | 否 |
| 稳定态最终贴图总量 | R=16 为 **1,582 种**；兼容所有非负视距为 **1,652 种** | 按需产生，不要求全部常驻 | 否 |
| 渐变中间图 | 只为正在发生的转换生成 | 0.25s 转换期间，单独短期缓存 | 否 |
| 磁盘缓存 | 可选，第一版默认关闭 | 用户启用或后续确认需要跨启动复用 | 否，运行时自行写入 |

“14 种”只描述二值轮廓；**开启浓度接边柔化后，最终缓存不会被限制为 14 张**。不以“47×4＝188 张”作为能覆盖所有浓度交界的保证，也不预制所有浓度排列。

C 的融合要求相邻雾格内部可连接，原来的“每格四边至少 4px 全透明”改为“实际雾区外轮廓向透明过渡”。全透明区域、容器孔洞和不可站立区域仍需保留。

现状：

- `BattleVisibility` 已读取关卡 `fog_of_war` 配置，提供基础揭示、攻击临时揭示、距离浓度和敌人可见性。
- `BattleFog` 已改为场景中的 Node，处理逐层坐标、可站立条件、容器例外、可见区节点和脏格更新；每格引用缓存贴图与逆变换。
- 浓度已烘焙进 RGBA 小图，稳定显示时节点 alpha=1；过渡采用 CPU alpha 插值。

## 3. 统一输入：逻辑浓度与显示浓度

### 3.1 逻辑浓度

用整数 `0/5/6/7/8` 编码，不将浮点字符串放进缓存键。

| 编码 | 遮罩不透明度 |
|---:|---:|
| 0 | 无雾 |
| 5 | 50% |
| 6 | 60% |
| 7 | 70% |
| 8 | 80% |

距离使用切比雪夫距离 `max(abs(dx), abs(dy))`：

- 视距内且射线通畅：0。
- 视距外第 1、2、3 格：5、6、7。
- 视距外第 4 格起：8。
- 视距内被墙体/障碍挡住：8。
- 攻击模式实际揭示：0。
- 迷雾关闭：所有格为 0。

### 3.2 显示浓度

在逻辑浓度基础上，处理渲染免雾条件：

```text
render_density(grid, level) =
    0                                      迷雾关闭
    0                                      没有地面或 terrain != 0
    0                                      静态障碍 tile 的 can_walk=false
    0                                      容器显示例外打开，且该格有 can_walk=false 容器
    logical_density(grid, level)            其他情况
```

显示浓度场只决定贴图。免雾容器格不写回基础视野，也不能据其显示浓度 0 显示敌人。敌人仍使用 `BattleVisibility.is_enemy_visible()`，即原始目标浓度阈值、视觉射线及攻击临时揭示。

不同楼层分别建立浓度场，不把上层邻格加入下层的图案计算。缺失地面、地图外部作为 0 处理。

## 4. 实际会出现哪些浓度接边

### 4.1 正常距离带

相邻格（含斜向）的切比雪夫距离最多相差 1。因此仅按距离，正浓度的不同档接边为：

```text
5 ↔ 6
6 ↔ 7
7 ↔ 8
```

正常距离带中不出现 `5↔7`、`5↔8`、`6↔8`。

### 4.2 特殊边界

- 视距内墙后区域会被设为 8，可紧邻视距外第一档 5。由于相邻格切比雪夫距离最多相差 1，它不会因此直接紧邻第二档 6 或第三档 7。
- 已揭示区域、攻击揭示、容器例外、不可站立格会产生 `0↔5/6/7/8`。
- 狭窄通道或孔洞可能让同一格同时面对两种以上边界，不能只按“一条边的两个浓度”缓存整格。

**第一版生成器接收完整 3×3 浓度输入，允许所有合法编码组合；正常距离带用于预测/预热，不作为拒绝特殊输入的校验条件。**这样未来规则扩展不会因为缓存假设而漏图。

`5↔7` 可作为生成函数的鲁棒性测试，不需要因正常关卡不存在这种接边而主动预制。

## 5. 47 规则、14 种基础轮廓与变换

### 5.1 八位编码

从上方开始顺时针：

```text
7 0 1
6 C 2
5 4 3
```

`bit[i] = render_density(neighbor[i]) > 0`。当前格浓度为 0 时不请求最终有雾资源。

### 5.2 47 规则

直边位为 `0/2/4/6`，对角位为 `1/3/5/7`。对于对角 d：

```text
normalized[d] = raw[d] AND raw[(d-1) mod 8] AND raw[(d+1) mod 8]
```

直边位原样保留。256 种二值输入归一化后是 47 种；再按正方形 D4 的 8 种变换（4 个 90° 方向 × 镜像与否）复用，得到 14 种。

**归一化只规定外轮廓的连接方式。**浓度场仍保留真实 3×3 数值供颜色/alpha 插值使用；被轮廓规则忽略的对角不能随意从浓度插值输入删除，否则相邻两格可能使用不同的采样数据而留下接缝。它不会因此新增二值轮廓母图，但会参与混合浓度缓存键。

### 5.3 基础轮廓清单

码串按上面的顺时针顺序阅读，最左字符是上方位，不依赖整数打印的大小端。此编号是开发文档中的固定编号，不直接等同于整数编码值。

| ID | 代表码串 | 说明 | 可展开状态数 |
|---:|---|---|---:|
| 01 | `00000000` | 孤立格 | 1 |
| 02 | `00000010` | 单向连接 | 4 |
| 03 | `00001010` | 相邻两向连接，对角缺失 | 4 |
| 04 | `00100010` | 相对两向连接，直通道 | 2 |
| 05 | `00001110` | 相邻两向连接，对角补齐 | 4 |
| 06 | `00101010` | 三向连接，两个相关对角缺失 | 4 |
| 07 | `00101110` | 三向连接，补齐一个相关对角 | 8 |
| 08 | `00111110` | 三向连接，两个相关对角补齐 | 4 |
| 09 | `10101010` | 四向连接，四个对角缺失 | 1 |
| 10 | `10101011` | 四向连接，补齐一个对角 | 4 |
| 11 | `10101111` | 四向连接，补齐相邻两个对角 | 4 |
| 12 | `10111011` | 四向连接，补齐相对两个对角 | 2 |
| 13 | `10111111` | 四向连接，只缺一个对角 | 4 |
| 14 | `11111111` | 完整内部格 | 1 |
| | | **合计** | **47** |

### 5.4 规范方向与逆变换

为 8 种变换建立固定枚举顺序，记录正向/逆向的九个采样位置排列。

```text
输入：中心值＋8 邻格原始浓度
对每个 D4 变换：
    同时变换二值轮廓和完整浓度分布
    candidate = (变换后的47状态码元组[0..7], 变换后的中心及邻格浓度)
选择字典序最小的 candidate
返回 canonical_key，以及从规范方向回到实际方向的 inverse_transform
```

不能只旋转二值形状，不旋转浓度分布。形状存在多重对称时，也必须用浓度分布消除朝向歧义；相同 candidate 的平局按固定变换编号处理，避免随机跳转。

先选定规范码元组，再查出对应的 14 形 ID；不要把对所有方向相同的“14 形 ID”直接放在首字段，否则浓度可能选出与基础轮廓不一致的朝向。

示例：

- 左 5、右 6 与左 6、右 5 可以镜像复用。
- 左 5、右 6 与左 5、右 8 不同缓存键。
- 三条边分别为 5、6、8 的图不能只按“当前格 6”查找。

显示时应用逆变换，旋转中心固定为格中心。Sprite 的翻转与旋转顺序不靠猜测：用对应 2×2 变换矩阵/位置置换测试确认。每次请求返回一个方向描述，不为每个实际方向另存 RGBA 图。

## 6. CPU 生成配方

### 6.1 不读取地面画面

输入只有显示浓度、归一化连接状态及固定样式参数。生成器不读取屏幕、不采样地面颜色，不按地图名称、坐标或玩家 ID 改变图案。同一个键在不同战局中应生成相同像素。

C demo 使用整片浓度场离线模糊。本方案改为局部、可缓存的小图配方，目标是保持相邻融合方向，**不承诺与旧 demo 逐像素相同**。

### 6.2 基础覆盖轮廓 G

尺寸第一版固定为 64×64。基础轮廓用单通道字节数组保存（0～255），不依赖生图。

将格子分为左上、右上、左下、右下四个 32×32 区域。每个区域读取相邻两条直边和对应对角，构成轮廓。先以建议宽度 `edge_width=12px` 制作评审样机，参数必须小于 32px。

令 `s(d)=smoothstep(0, edge_width, d)`，d 是像素到对应格边的距离：

| 两条直边是否连接 | 对角 | 该角区域覆盖值 |
|---|---|---|
| 都不连接 | 忽略 | `s(d1) × s(d2)`，两侧向透明过渡 |
| 仅第一条连接 | 忽略 | `s(d2)` |
| 仅第二条连接 | 忽略 | `s(d1)` |
| 两条都连接 | 有雾 | 1 |
| 两条都连接 | 无雾 | `s(sqrt(d1²+d2²))`，柔化内凹角 |

这是首版的确定性几何配方，外观仍由用户评审。四区域中线处必须饱和为兼容值；公共边使用相同距离约定和采样中心，不独立手调每张图。

为避免浮点旋转导致像素不一致，可在整数像素中心 `(x+0.5,y+0.5)` 计算，通过精确的 90° 索引置换产生方向变化。

### 6.3 浓度过渡 C

只用形状乘本格浓度会让 5/6 接边仍有台阶，因此混合浓度请求还需要烘焙浓度场。

建议配方：

1. 将真实 3×3 浓度看成九块恒定小区域，正浓度除以 10 得到 alpha。
2. 对正浓度区域做有限支持的、可分离的高斯加权；建议 `density_sigma=11px`，核截断半径 33px，小于一个格宽。
3. 使用归一化插值，避免无雾邻格把已由 G 处理的外边缘重复压暗：

```text
A = 加权后的正浓度值总和
B = 加权后的有雾指示值总和
C = A / B                   B > epsilon
C = 本格浓度                其他情况
final_alpha = G × C
```

无雾邻格在 A、B 中均为 0；外边界由 G 负责。在全为 5 的有雾区域，C 应恒为 0.5，不应被无雾背景再次稀释。

高斯权重可预先缓存为“像素位置到左/中/右三个格区间”的一维积分权重；二维权重是两轴乘积。每个输出像素最多结合 9 个输入值，无需每次创建 192×192 大图并调用通用模糊函数。

共享边两侧必须等价于采样同一个局部浓度场，核参数相同、支持半径固定。真实浓度包含对角输入，避免在边端点丢失信息。

### 6.4 最终像素与透明度

先保持 C demo 使用的统一 RGB `(66,84,94)`，仅 alpha 随轮廓与浓度变化。此为已有技术 demo 色彩，不表示正式美术配色通过评审。第一版不加定向光照、随机噪声或坐标纹理，保证旋转/镜像复用与公共边一致。

最终 RGBA 图已经烘焙 **绝对目标 alpha**：

```text
final_alpha = clamp(G × C, 0, 0.8)
RGB = 固定样式颜色
```

**节点不能再乘 0.5/0.6/0.7/0.8。**否则 50% 贴图再乘 50% 会变成 25%。正常稳定显示时 `modulate.a=1`；动画的过渡系数与玩法浓度是两回事，见 §10。

当前格显示浓度为 0 时不放置雾贴图，图案也不越出 64×64。容器免雾格和已揭示格因此不被相邻图盖回去。

## 7. 缓存结构与资源数量

### 7.1 L0：拓扑与变换表

256 个原始二值 mask 对应 47 规范状态和 14 基础形状。记录 mask 归一化、对应母形、可用变换列表。该层是少量整数，不是图片。

完整浓度分布的规范方向仍需在候选变换中选取，不能只用 L0 中任意一个形状朝向。

### 7.2 L1：14 种基础轮廓

```text
ShapeKey = (shape_recipe_version, size, edge_width, canonical_shape_id)
ShapeEntry = {
    coverage: PackedByteArray          # 64×64 个单通道字节
}
```

单一样式下最多 14 项，不做 LRU；战场退出或样式版本变化时整体释放。14 个 64×64 单通道轮廓合计约 **56KiB** 原始像素。首次用到生成，加载阶段可分帧把这 14 个基础轮廓预热齐。

### 7.3 L2：最终浓度贴图

当前格 3×3 范围内，所有有雾邻格都与本格同浓度时可走快速路径：

```text
uniform key = (recipe_hash, "uniform", shape_id, own_density)
alpha = G × own_density
```

相同形状/浓度不必因无关原始邻格差异重复存图。均匀图理论上最多 56 项；按需产生，不强制全部预热。

存在不同的正浓度时：

```text
mixed key = (
    recipe_hash,
    "mixed",
    canonical_shape_id,
    canonical_center_density,
    canonical_neighbors[0..7]
)
```

所有浓度用整数、固定字段顺序。键不包含楼层编号、地图坐标、玩家位置、距离 R、节点 ID；这些信息已通过浓度输入表达，放进去会妨碍复用。

`recipe_hash` 覆盖：

```text
生成器版本、47规则版本、像素尺寸、边缘宽度、
核参数、核截断半径、颜色、颜色空间/alpha约定
```

默认不把样式版本变化后的资源混在同一个桶中。

```text
TextureEntry = {
    key: String,
    texture: ImageTexture,
    alpha: PackedByteArray,             # CPU 侧保留，供过渡使用，禁止 GPU 回读
    hash: String                       # alpha 内容 SHA-256
}
```

READY、PENDING 与失败请求分别由 `entries`、`pending`、失败键集合管理。尺寸由固定 recipe 决定，像素估算在 `get_stats()` 中计算，不为每个条目重复保存。

如果统一声明 RGBA8、64×64、不生成 mipmaps，每张 RGBA 原始像素约 **16KiB**，另保留 **4KiB** CPU alpha 数组；上传用的临时 RGBA 缓冲可在上传后释放。同浓度 56 张的 RGBA 像素约 **896KiB**，另有 224KiB CPU alpha；稳态缓存固定容量 2,048 项，按需生成并常驻当前战场。过渡不得调用 `Texture2D.get_image()` 从设备回读，直接使用保留的 CPU alpha。

### 7.4 按当前规则可出现的组合数

**视距 R=16 时，按当前缓存定义，共 1,582 个可出现的稳定态缓存键。**此处已包含正常距离带、任意关卡布局可产生的无雾孔洞、视距内墙后 8、47 几何归一化、D4 复用和均匀浓度快速路径。不是任意打乱五种浓度的输入全集，也不是要求当前新手地图必须把所有组合用齐。

| 纳入的规则 | 去重后的稳定态缓存键数 |
|---|---:|
| 只有正常切比雪夫距离带，没有额外孔洞或墙后覆盖 | 13 |
| 正常距离带＋地图边界、不可站立地形、容器等无雾孔洞 | 1,100 |
| 再纳入视距内墙后 8 的特殊接边 | **1,582** |

这 1,582 项按本格浓度分解为：

| 本格浓度 | 均匀快速路径 | 混合浓度键 | 合计 |
|---|---:|---:|---:|
| 5 | 4 | 374 | 378 |
| 6 | 4 | 374 | 378 |
| 7 | 4 | 374 | 378 |
| 8 | 14 | 434 | 448 |
| **合计** | **26** | **1,556** | **1,582** |

因此，§1/§7.3 的“均匀图最多 56 项”是生成器通用能力；按当前距离规则，实际只需其中 26 项。

#### 枚举方法与完整性

复现脚本：`tools/count_fog_cache_combinations.py`。

1. 固定观察者为 `(0,0)`，用 `d=max(abs(x),abs(y))` 直接计算实际距离带，而不是枚举任意浓度。
2. 利用旋转/镜像对称，只需遍历第一象限中的局部 3×3 窗口。中心坐标遍历至 `R+5`：再远时九格全部在稳定的 8 区域，不增加模板。
3. 视距内以“可能遮挡的 8”为基准，视距外按固定 5/6/7/8 分档；对可以清空的格枚举 0。0 代表真实视野、攻击揭示、地形/地图孔洞或容器免雾，而不是任意改成另一档正浓度。
4. 任意关卡可以通过不可站立/缺失地面形成所需孔洞；全遮挡的视距内区域可以通过墙体构造，再用孔洞清空局部格。因此此枚举允许的正浓度不依赖“任意独立射线可见性”假设。
5. 对每个合法局部输入，调用与文档定义一致的 47 归一化、D4 联合浓度规范化和均匀快速路径，统计唯一 key。R=16 得到 4,360 个代表象限的有向数值窗口，合并为 1,582 键。
6. 检查所有相邻位置（含斜向）：不同正浓度对只可能是 5/6、6/7、7/8、5/8，不能混入 5/7 或 6/8。

此数按“所有符合当前规则的关卡布局”统计，当前一张有限地图会使用其子集。不包含中间动画 alpha、不同样式/尺寸参数版本或节点 ID。

#### 可配置视距的边界情况

- R≥1 的局部类型相同；脚本逐项验证 R=1..16 的 key 集完全相同，并复查 R=32。
- R=0 会出现单格视距的特殊局部形态。将跨楼层情况一起覆盖时，该坐标在非玩家楼层可以未揭示，不应强制所有楼层的观察者坐标都为 0。
- R=0 自身有 1,311 键，其中 70 个不在 R≥1 集中。
- **要兼容配置允许的全部非负视距，应覆盖 1,652 个唯一稳定态键**（1,582＋70），不是将各视距数量重复相加。

#### 资源估算与方案选择

1,582 张 64×64 RGBA8 原始像素约 **24.72MiB**，另保留 CPU alpha 约 6.18MiB；覆盖全部非负视距的 1,652 张约 **25.81MiB** RGBA，另有约 6.45MiB CPU alpha。均不含引擎对象、临时缓冲和纹理额外副本。

用户已指定采用足以覆盖合法全集的容量：**0 张预制 PNG、14 种基础轮廓、按需生成＋2,048 项字典缓存**。生成后保留到退出战场，不做稳态 LRU 淘汰。加载阶段是否预热全部 1,652 项仍是单独的启动策略，默认按需。渐变 L3 单独计数，不占稳态条目。

当前实现为首次混合浓度请求提供同步的均匀浓度轮廓占位，避免开局等待期间全图无覆盖。它复用同一个字典中的 uniform 键，最多补齐通用 56 种 uniform 中不在合法稳态 26 种内的 **30 个辅助键**。因此“完整合法稳态＋所有占位”的字典上界为 **1,682**，仍小于 2,048；不改变玩法可出现的 1,652 稳态组合数。

此前的 **201,752** 是未施加玩法空间规则的生成器全输入域，不再作为本方案的资源量依据。

## 8. 固定容量、生命周期与存储位置

### 8.1 首版默认内存缓存

缓存服务由当前战场持有，所有楼层共享，退出战场整体释放，暂不新增全局自动加载。稳态贴图保存在普通 Dictionary 中，稳定画面不重复生成、不调用纹理 update。

初始预算：

| 缓存 | 建议预算 | RGBA 纹理原始像素估算 | CPU alpha |
|---|---:|---:|---:|
| L1 轮廓 | 14 个 | 不创建纹理 | 56KiB，单通道 |
| L2 稳态贴图 | 2,048 项固定容量；合法全集最多 1,652 | 额度对应 32MiB | 额度对应 8MiB |
| L3 活跃过渡帧 | 64 张软预算，不占 L2 | 1MiB | 256KiB |

实际生成完整 1,652 项时，L2 约 25.81MiB RGBA＋6.45MiB CPU alpha；并非一开始分配满 2,048 项。额度全满且计入表中 L1/L3 时约 41.31MiB 像素数据估算，不含 Godot 对象、临时缓冲和引擎其他副本。

生命周期规则：

1. 首次 miss 才创建条目，命中直接返回同一个不可变资源；不维护最近使用顺序。
2. 稳态贴图生成后即使暂时无格子引用，也保留在字典中，直至退出战场。
3. 过渡帧和快速反向的中间快照只归 L3，禁止塞进 L2，避免人为突破 1,652 种稳定态范围。
4. 同一缓存实例只使用一个 recipe；颜色、尺寸、羽化宽度等参数变化时重建显示节点并整体重建缓存，不把多套样式堆进同一个 2,048 项字典。
5. 正常规则及辅助占位不应达到 2,048 项。若容量检查触发，报告键数量异常，检查非法浓度、遗漏规范化、recipe 混用或过渡帧误入；不通过静默 LRU 淘汰掩盖问题。当前需求保留显示或用基础占位，不访问越界条目。
6. 相机可见区节点可独立创建/销毁，不影响已有稳态缓存；退出战场时统一清空字典、pending 与过渡资源。

无需双向 LRU 链表、最近使用时间或稳态资源的淘汰扫描。

### 8.2 同一请求去重

`pending_jobs[key]` 保存待完成请求。多个格子需要同一贴图时只入队一次，并登记多个订阅者。失败请求记录短期失败状态和原因，不每帧无限重试。

订阅者必须携带 `(cell_key, request_revision)`。异步返回时，如果角色已移动导致该格需求变化，丢弃旧绑定；计算完成的纹理仍可按缓存策略保留，不能把旧图覆盖新状态。

### 8.3 可选磁盘缓存

首版不必开启：14 个基础轮廓很小，内存命中即可受益。若实测发现冷启动生成开销有必要跨启动复用，再增加：

```text
user://cache/battle_fog/<recipe_hash>/<sha256(canonical_key)>.png
user://cache/battle_fog/<recipe_hash>/<sha256(canonical_key)>.json
```

- 只持久化最终稳定贴图，不写每个动画中间帧。
- JSON 保存完整键、尺寸、格式、算法版本；读盘时检查与请求完全一致。
- 写 `.tmp` 成功后原子改名，避免中断留下半张文件。
- 读盘失败、格式不符或版本不同：忽略缓存并重新生成，不影响战斗。
- 可设置如 32MiB 的实际文件字节预算；PNG 压缩率不作为固定内存承诺。
- 不写入 `res://Art/`，不触发 Godot 编辑器导入，不把运行时缓存写进游戏存档或提交 Git。

以上路径是设计，不是本轮创建的实际文件。

## 9. 缓存未命中时的工作流

```text
关卡/单位状态变化
  → 逻辑层更新浓度与敌人显隐
  → 显示层建立新的 render_density
  → 比较新旧浓度，得到 changed_cells
  → dirty_cells = changed_cells 及同层八邻格
  → 每个待显示 dirty cell 收集 3×3 输入
  → 47 轮廓归一化＋浓度整体 D4 规范化
  → READY 缓存命中：共享纹理＋逆变换
  → PENDING：追加订阅者
  → 缺失：排队 CPU 生成
  → 主线程创建 ImageTexture，登记缓存
  → 校验 revision，再更新节点和渐变
```

由于核截断半径 33px 小于 64px，单格输入只依赖 3×3，改变一格后扩大一圈刷新足够；扩大核支持半径时，必须同步修改依赖范围和缓存版本。

排队策略：

- 相机可见格、刚揭示/遮挡格、其他缓冲格按顺序处理。
- 初始软预算建议每帧最多 2 个新贴图任务，或 CPU 生成消耗达到 2ms 时停止继续取任务；单个任务不能中途抢占，2ms 不是硬保证，需实测。
- 可先主线程分帧处理 64×64。确有需要时再将纯像素数组计算移到 WorkerThreadPool，场景节点和 ImageTexture 创建留在主线程。
- CPU 生成的纹理上传属于普通贴图资源流程；不做 GPU 模糊或回读。

当前使用主线程分帧。基础轮廓和均匀占位首次需要时同步产生并复用；2 张/2ms 软预算针对排队的混合浓度贴图，不是整个视野刷新或同步占位工作的硬时限。场景加载前首次建遮罩不播放全图淡入。

排队期间：

- 显隐权限立即按新逻辑状态更新；不能等资源就绪才隐藏敌人。
- 完全揭示/免雾孔洞需要及时撤去对应遮罩，不能用邻格填充图挡住容器。
- 已有贴图可短暂保留等待形状更新；新出现格可用 L1 快速生成的本格均匀浓度图作临时占位，不等待混合浓度任务。
- 临时占位及最终过渡都须用户实机评审；不能把任务预算等同于无延迟保证。

## 10. 与 0.25 秒渐变的兼容

### 10.1 为什么不能直接沿用当前浓度调制

当前 `BattleFog` 的单张贴图没有烘焙浓度，节点 alpha 就是浓度。本方案最终贴图已包含浓度及边界过渡，应改为“在旧最终像素与新最终像素间过渡”，玩法目标值另存。

### 10.2 不用 Shader 的过渡方案

首版建议在 CPU 上对**已生成的旧/新 alpha**做小图插值，不重新计算模糊：

```text
alpha(t) = old_alpha × (1-ease(t)) + new_alpha × ease(t)
ease(t) = (1-cos(pi*t))/2
```

RGB 第一版为统一颜色，只需插值 alpha。普通两层 Sprite 分别乘 `(1-t)` 和 `t` 再 source-over 叠加，不能得到上述精确插值，会有额外乘积项；不把它当作精确的浓度过渡。

为减少同一转换在多个节点上重复计算：

- 0.25s 分为 6 个步进（约 24fps 的过渡采样），可在 demo 中对比是否需要 8 步；不是长时间烟雾动画帧。
- L3 键包含 `(old_content_hash, new_content_hash, 相对方向, step_index, recipe_hash)`。旧/新资源先变换到相同的规范画布，实际图在格子中方向不变。
- 每个过渡帧首次需要时做 CPU alpha 插值，共享给相同转换的节点。L3 暂以 64 张作软预算，仅保存活跃转换；最后一个动画订阅者释放后直接删除，不维护 LRU。终点只引用 L2 稳态图。
- 如果没有足够内存缓存过渡帧，可使用活跃转换的单个临时 ImageTexture 更新像素；需单独统计 CPU/上传成本，不默认更快。
- 快速反向时，以**当前实际显示的过渡帧 alpha**为新起点，生成内容哈希；不能回到旧稳态起点。该中间图只在过渡期间引用，不进入长期稳态 L2。
- 隐藏到无雾的目标图使用共享全透明缓冲，结束后释放格子 Sprite。
- 开局直接显示目标状态，不播放全图动画；节点销毁取消订阅并 release 资源。

渐变步进是否足够平滑由用户评审，不能根据公式自行宣告动画效果合格。该方案无每帧全图模糊，但过渡期间仍有小图生成/上传成本，必须纳入实测。

当前仅遍历活跃渐变格，稳定画面不遍历所有 Sprite 做插值。若同一时刻被引用的过渡帧超过 64，保留活跃帧并记录 `transition_budget_exceeded`，不误删正在显示的帧；下一阶段释放订阅后立即回收。此项是软预算，不宣称硬限制在 64 张。

## 11. 需要落地的接口

```text
FogNeighborhood.build_render_densities(manager, visibility, tree)
    → {densities: Dictionary[Vector3i,int], immediate_clear: Dictionary}

FogNeighborhood.canonicalize(samples: PackedByteArray)
    → {key, shape_mask, samples, transform, uniform}
FogNeighborhood.inverse_transform(transform)

FogNeighborhood.dirty_neighborhood(previous, current)

FogMaskGenerator.get_shape(canonical_mask)
    → PackedByteArray

FogMaskGenerator.generate_alpha(descriptor)
    → PackedByteArray

    → Image

FogMaskCache.request(descriptor, cell, revision, priority)
    → READY entry 或空字典（pending/failed）
FogMaskCache.uniform_placeholder(descriptor)
FogMaskCache.process_generation_budget(max_jobs, max_usec)

FogMaskCache.begin_transition(...) / get_transition_frame(...)
FogMaskCache.release_transition_frame(...) / end_transition(...)
FogMaskCache.get_stats() / clear_all()

BattleFog.refresh(...)
    → 更新逻辑目标、dirty 邻域、纹理绑定和过渡
```

`Texture2D` 缓存项视为不可变。共享资源不得通过 `update()` 给某个格子单独改透明度，否则所有共享它的格子都会被改动。可更新资源仅限明确标识的临时过渡纹理。

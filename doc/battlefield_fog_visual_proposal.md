# 战场迷雾遮罩优化提案

2026-11-23 · 待用户确认的美术方案。本次只提案，不生成新素材，不采用先前已被用户否定的候选。配置、距离浓度和显隐规则已实现，见 `battlefield_combat_design.md` §10。

**最新方向与实现**：用户选择 demo C 的相邻融合效果，不使用 GPU 特效计算，进一步同意 47 邻接规则及旋转/翻转复用，并授权按文档开发。当前以 [battlefield_fog_cache_development.md](battlefield_fog_cache_development.md) 为准：14 基础轮廓、0 张预制母图、CPU 按需生成、2,048 项缓存及 CPU 渐变均已接入。§8 的完整预制图集是前一阶段路线；§1～6 的逐格四边留白及生图提示词作为历史探索保留，不再作为当前生产要求。实际生成器样例已交付 `_review/fog_of_war/cpu_cache/`，观感仍由用户评审。

## 1. 建议方向：低饱和战术雾片

沿用当前战场的蓝灰路面、灰绿物资箱与简化块面。迷雾采用 **一格一个中央独立的、不对称雾片**，读起来是环境遮挡，减少圆形云朵图标的感觉。二次元的表现来自概括的轮廓、两至三块明暗与少量手绘边缘；浮世绘影响只保留在一两处收笔，不加入祥云、海浪或连续装饰纹。

设计要点：

- 主体是一块横向或斜向的扁平不规则雾片，内部最多两块次级阴影；减少小圆泡、旋涡和多条刻线，保证缩到 64×64 后仍能分辨主体。
- 中心略实、外沿少量软化，边界宽约 2～3px；四周至少 4px 全透明，轮廓不做方形边框，不依靠整体高斯模糊。
- 起始配色建议为阴影 `#34464E`、主体 `#5D7379`、小面积亮面 `#879A9D`；这是待评审色卡，不代表已定稿。主体不使用纯黑或大面积亮白。
- 图案核心 alpha 可为 1，四周 alpha 为 0；**距离浓度交给运行时**，不把 50/60/70/80% 烘焙成四套图片。已有素材若核心 alpha 只有 0.4，运行时 0.8 最终也只有 0.32，无法表达要求的遮挡浓度。

## 2. 降低“每格一枚相同贴纸”的重复感

建议用户确认方向后，再制作 A/B/C 三个轮廓变体：左侧偏重、右侧偏重、斜向短尾。三版尺寸、透明留边、色卡和平均覆盖面积接近，不以随机改变透明度制造差异。

用 `(grid.x, grid.y, level)` 的固定哈希选图，角色移动或重新起雾时保留相同变体，不每帧随机、不在显隐时换形。采用自然方向变化，不将有明确体积光面的图案任意旋转，避免亮面方向混乱。

本次没有实现多变体；它属于确认后再推进的视觉方案。

## 3. 动画：先保留显隐渐变，内部运动另行评审

- 保留已实现的逐格 **0.25s Sine EaseInOut**，支持 0%、50%、60%、70%、80% 之间连续过渡，中途反向从当前值接续。
- 敌人显隐按逻辑浓度立刻判定，不按 tween 中间帧判断，避免 70%/80% 边界上忽隐忽现。
- 暂建议不加闪烁、呼吸式 alpha 或大幅缩放，这些会让“70% 可见”规则难以理解。
- 若静态轮廓通过用户评审，再考虑前景雾片 1px 左右的缓慢位移、周期约 5～7s、每格固定错相；运动始终裁在原 grid，四周留白不会漂到邻格。此项尚未实现或生成动画。
- 暂不建议 UV 整面滚动：当前需求是独立格留白，连续纹理滚动会与这个结构冲突。

## 4. 与玩法显示的关系

| 对象/区域 | 表现 |
|---|---|
| 基础视野及攻击模式实际揭示格 | 不覆盖遮罩 |
| 视距外第 1/2/3 格 | 目标浓度 50/60/70%；射线无阻挡时敌人可见，仍受雾片叠色 |
| 视距外第 4 格起 | 目标浓度 80%，敌人隐藏 |
| 视距内被墙体/中间障碍挡住 | 目标浓度 80%，敌人隐藏 |
| 视距外但射线被挡住 | 雾片按距离浓度显示，敌人仍隐藏 |
| `show_blocking_containers=true` 的 `can_walk=false` 容器 | 容器正常显示，该格雾片退去，不向后传播视野 |
| `can_walk=true` 的容器/掉落物 | 不享受例外；不能因此把站在上面的敌人显示出来 |
| 墙体与不可站立静态 Tile | 保留原先不铺雾的规则，不能用“没有雾片节点”推断敌人可见 |

## 5. 制作与用户评审步骤

1. 先制作 **一张 A 版**，交付 1024×1024 原始母版、同尺寸透明母版、64×64 单格。
2. 附上原尺寸单格、4×4 排列、真实战场风格合成，以及相同图案 50/60/70/80% 并排预览。合成图明确标注不是实机截图。
3. 用户先确认轮廓、配色和遮挡强度，再制作 B/C；避免在基础方向未确定时大量生成。
4. 用户确认静态图后，再做渐变及小幅位移的实机评审。
5. 素材全部先入 `_review/`，原始图与备选一并交付，不由 Agent 自评分或择优。用户批准后才转正式目录并登记 manifest。

## 8. 已选 C 的素材实现路线：预制边界图集

### 8.1 限定

不引入自定义 Shader、Compute、屏幕采样、实时高斯模糊、运行时生成雾纹或每帧重建大图。边缘羽化和图案连接在制作阶段烘焙进 RGBA 贴图。游戏仍使用 Godot 常规 2D 贴图显示与现有透明度调制；不将“没有额外 GPU 特效计算”表述为整个 Godot 场景完全不使用 GPU 绘制。

### 8.2 图集结构

- 区域内部用连接填充格，相邻都有雾时不在格缝强制留透明边。
- 雾区外轮廓用上/下/左/右羽化边，转折处用内角/外角；孤立格用四周羽化的独立形。
- 以八邻域的标准 47 种 blob 拓扑组织完整边界图集，运行时每格只选一张对应区域；不是生成一张整张战场大小的贴图。
- 固定方向的贴图接缝在制作时统一，减少光面被任意旋转的问题。风格仍是低饱和蓝灰、二次元概括块面与克制的轮廓收笔，静态图案由用户评审。
- 47 种只覆盖“有雾/无雾”的拓扑，不能自动解决不同浓度之间的过渡。50/60/70/80% 保持原逻辑值；如 10% 浓度分界仍明显，另制作预烘焙的浓度连接边，不承诺单套 47 格就能完全复现 demo 的连续模糊。

**约束变化**：C 的连续感要求相邻覆盖格能连起来，因此“每格四边至少 4px 全透明”改为“只有雾区外轮廓向透明过渡”。若保留每格透明缝，就只能得到 A/B 的独立格效果。

### 8.3 运行时仅处理格子状态

1. 视野/浓度变化时更新发生变化的格及其最多八个邻格，按楼层分别选图；不每帧遍历整张地图重新处理像素。
2. 基础视野、攻击临时揭示、不可站立 Tile 和开启例外的阻挡容器格作为无雾孔洞；周边图案使用对应内边/内角，不把孔洞重新盖住。
3. 原有 0.25s alpha 渐变保留。若邻接状态导致图集形状变化，新旧图形也需做过渡，不能在淡出中突然切边；具体接线在用户确认样张后实现。
4. 敌人显隐继续按目标逻辑浓度和射线判断，不能读取图片像素或透明边缘。容器例外不传播视野。

代价主要转为前期素材制作及图集内存。47 张 64×64 RGBA 的原始像素约 0.73MiB（不含图集空位、导入格式与 mipmaps）；若整齐放在 512×512 图集，单层未压缩 RGBA 为 1MiB。额外浓度连接边、轮廓变体或动画帧会相应增加资源占用。本次未实测运行时性能，不作帧耗时保证。

### 8.4 后续 demo 与评审

下一批应交付“纯贴图拼接”的 C 方案：先做一组中心、直边、内外角和孤立格，展示大片雾、窄通道、单格孔洞、50/60/70/80% 交界及渐变前后。不把现有离线模糊合成图冒充该素材方案已实现的效果。

样张、拼接图和动画全部放 `_review/`，由用户确认边缘和图案后再扩展完整图集。当前只更新提案，不自动生成、替换或入库素材。
